# Автоматическое построение и отбор признаков для рекомендаций

Решение задания 1 T-Lab. Основная задача: предсказать следующий просмотр товара по всем уже известным действиям пользователя. Сравниваются содержательный ручной CatBoostRanker, автоматически выбранные оконные признаки, сочетания, оба семейства и случайный контроль того же размера. Полный протокол до тестовой оценки: `PROTOCOL.md`.

## Данные и отличие от предварительного пилота

Используется открытый REES46, файл за **весь октябрь 2019**, https://data.rees46.com/datasets/marketplace/2019-Oct.csv.gz. Выбраны 5 000 пользователей по фиксированному хешу ID; сохранены **все 71 429 событий** этих пользователей за месяц, включая разные посещения. Независимый повторный проход всех 42 448 764 исходных строк подтвердил количество и хеш каждой строки для каждого выбранного пользователя (`results/full_history_verification.json`). Дополнительное ограничение числа обучающих моментов не удаляет пользовательскую историю.

Данные REES46 выбраны из-за просмотров/корзины/покупок, времени, категорий, брендов и цен. Это осознанная альтернатива приведённым в задании KION/Yambda. Исследование относится к следующему просмотру, не к CTR после показа или вероятности покупки. Фильтры доставки, фотографии и истинный бюджет не наблюдаются.

Ранний пилот использовал выборку посещений и только сессионную историю. Он выявил полезные направления, но **не является итоговым экспериментом** и его числа не объединяются с новым результатом. В финале история пользователя охватывает все известные к моменту прогноза события разных посещений. Новая итоговая проверка:25-30 октября; обучение:2-20; validation:21-24. Цели, пересекающие границы, исключены; сами сырые события сохранены.

## Метод

Соответствие критериям задания:

| Критерий | Где проверить |
|---|---|
| Ручной бустинг и воспроизводимость | `manual_features.py`, `encoding.py`, `train.py`, `run_pipeline.py` |
| Реализованная автоматизация | `feature_library.py`, `select_features.py`, `results/selection.json` |
| Сопоставимый эксперимент | `PROTOCOL.md`, `evaluate.py`, `test_gate.json`, сохранённые прогнозы |
| Анализ качества и затрат | PDF, `RESULTS.md`, `results/test_results.json`, записи времени и RSS |

Выбранный список признаков общий для всех запросов; значения пересчитываются по доступному на каждый момент префиксу. Это глобальный отбор признаков, а не персональный выбор окна для каждого запроса.

Ручная база:105 числовых и 3 категориальных признака, включая активность, популярность, прямую историю товара, категорию/бренд, цены и окна 3/10 событий, вся история, 1/7 дней. Алгоритм генерирует 112 дополнительных оконных агрегатов и 48 сочетаний из фиксированного словаря операций. Медианы/границы/корреляции рассчитываются на train; отбор по согласованности с ошибками ручного бустинга проводится **на validation**, со стабильностью в двух временных блоках и отсевом дубликатов внутри семейств. До 12 признаков каждого типа. Словарь создан человеком; автоматичны перебор и отбор, а не свободное изобретение формул.

Все пять вариантов используют одинаковые данные, 200 кандидатов, 261 дерево глубины 6 и три seed. CatBoostRanker/QuerySoftMax, lr.06, l2=5, SkipTest, без ранней остановки. Первичное сравнение заранее задано:оба семейства минус ручная база по NDCG@20. Семейства по отдельности и случайный контроль помогают интерпретировать результат; лучший тестовый вариант не подменяет заранее выбранный метод. Подбор гиперпараметров сверх фиксированных параметров пилота не проводился.

## Как воспроизвести

Для подачи доступны два архива. **`tlab_submission_code.zip`** содержит код, отчёт, протокол, результаты и сохранённые прогнозы; исходные события, снимки каталога и модели в него не включены. **`tlab_submission.zip`** дополнительно содержит эти данные и 15 обученных моделей. Оба архива относятся к одному и тому же эксперименту.

Python3.12, CPU, желательно 16 ГБ RAM. GPU не требуется. Одновременно обучаются две модели по 4 потока. Длительность зависит от процессора; реальные измерения находятся в`results/*_202610*.json`, `results/feature_manifest.json`, `results/test_results.json`.

```bash
python -m pip install -r requirements.txt
python verify.py --outputs-only
```

Команда выше подходит обоим архивам: проверяет метрики по сохранённым прогнозам, интервалы и диагностику отбора, без обучения. Она не проверяет отсутствующие в небольшом архиве файлы данных и моделей и не перезаписывает сохранённый протокол полной проверки. В полном архиве дополнительно доступна проверка контрольных сумм данных и моделей:

```bash
python verify.py
```

`verify.py` проверяет готовые результаты по топ-20ID/рангам, интервалы, контрольные суммы и запись полной истории, без повторного обучения.

Полный повтор из поставляемой выборки и дневных снимков (**только полный архив**), в новую папку:

```bash
python run_pipeline.py --output /absolute/path/tlab_reproduced
```

Повтор со скачиванием исходного файла и независимой проверкой полного исходного потока (**оба архива**; примерно 1.74 ГБ сетевого трафика на каждый из двух проходов):

```bash
python run_pipeline.py --output /absolute/path/tlab_from_source --download
```

Все пользовательские события сохраняются до разделения моментов прогноза. Префиксы и снимки каталога используют только прошлое. Целевые поля не передаются в генераторы. Правильный товар не добавляется в кандидаты; непокрытые запросы имеют нулевую итоговую метрику. Тест открывается после фиксации кода/моделей/отбора в`test_gate.json`.

## Файлы

- `data/events_all.csv.gz`, `selected_users.json`, `extraction_manifest.json`: полная выборка пользователей.
- `data/queries_*.csv.gz`: моменты прогнозов и цели, временное разделение.
- `data/catalog_daily/`: одинаковая доступная историческая информация о товарах (исторические снимки октября 2019).
- `results/selection.json`, `feature_screening.csv.gz`: выбранные признаки и причины отбора/отсева.
- `models/`:15 зафиксированных моделей.
- `results/test_per_query.csv.gz`, `test_top20.npz`, `test_results.json`: проверяемые прогнозы, метрики, интервалы, группы, стоимость.
- `results/verification.json`: независимые проверки.
- `output/pdf/tlab_final_report.pdf`: итоговый отчёт; `RESULTS.md`: краткие таблицы и ограничения.

Большие матрицы признаков в`cache/` воспроизводятся и в архив не включаются. `SHA256SUMS` проверяет содержимое файлов архива.

## Использование инструментов

ChatGPT/Codex использовались для разработки экспериментального протокола, написания и проверки кода, запуска вычислений и подготовки материалов. Исходная мотивация учитывать текущий ценовой интерес, категорию и смысл действий сформулирована кандидатом; интерпретация ограничений обсуждалась совместно. Это не заявление о самостоятельном написании кандидатом всего кода. Автоматический поиск признаков внутри эксперимента реализован отдельным алгоритмом и не равен факту использования ChatGPT при программировании.

## Источники

- REES46, официальный источник: https://data.rees46.com/ ; фактические типы событий в октябрьском файле проверены при чтении.
- CatBoost, официальная документация ranking objectives: https://catboost.ai/docs/en/concepts/loss-functions-ranking .

Новизна самого учёта цены/истории или грамматического перебора признаков не заявляется. Итоговый вывод определяется измерениями на зафиксированном отложенном периоде; положительный прирост не является условием корректности исследования.

Если доверительный интервал включает ноль, это не доказывает равенство качества или отсутствие потерь. Для формального вывода о неухудшении потребовался бы заранее заданный допустимый порог; в этом эксперименте он не устанавливался.
